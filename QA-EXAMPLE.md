# Пример чек-листа для редактора

Этот документ подготовлен для портфолио. Он показывает, как можно описать общие проверки проекта с кадрами и сохранением. Это предложение сценариев, а не внутренний тест-план MULTIKIT и не доказательство наличия всех перечисленных функций.

Все проверки пока имеют статус **Не выполнялся**. Для реального прогона нужно записать версию приложения, ОС и окружение, согласовать ожидаемое поведение и приложить обезличенные доказательства.

## Данные для примера

Использовать только созданные для теста изображения: три одноцветных PNG с номерами 1, 2 и 3. Проект назвать `demo-project`. Работать в отдельной временной папке без личных файлов. Сценарии с повреждёнными копиями выполнять только над тестовыми данными.

| ID | Что сделать | Предлагаемый ожидаемый результат | Статус |
| --- | --- | --- | --- |
| ED-01 | Создать пустой проект | Редактор показывает пустое состояние без ошибки | Не выполнялся |
| ED-02 | Импортировать три тестовых изображения | Появляются три кадра в понятном порядке, содержимое читается | Не выполнялся |
| ED-03 | Поменять местами первый и последний кадры | Порядок меняется, состав кадров сохраняется | Не выполнялся |
| ED-04 | Удалить один кадр, затем выполнить отмену, если она предусмотрена | Кадр и его положение восстанавливаются | Не выполнялся |
| ED-05 | Сохранить тестовый проект, закрыть и открыть его | Кадры, порядок и сохранённые параметры совпадают | Не выполнялся |
| ED-06 | Изменить проект и отменить его закрытие | Проект остаётся открытым, изменения сохраняются в текущем сеансе | Не выполнялся |
| ED-07 | Убрать один исходный файл из тестовой папки и открыть копию проекта | Приложение сообщает об отсутствии файла и не портит остальные данные | Не выполнялся |
| ED-08 | Предложить для импорта неподдерживаемый тестовый файл | Понятная ошибка; редактор остаётся доступным | Не выполнялся |
| ED-09 | Уменьшить окно и пройти основные действия с клавиатуры | Нужные элементы доступны, фокус видим | Не выполнялся |
| ED-10 | Экспортировать короткий тестовый проект, если экспорт предусмотрен | Файл создаётся, открывается и содержит ожидаемую последовательность | Не выполнялся |

## Как записать дефект

Для найденной проблемы нужны: короткий заголовок, версия и окружение, предусловия, шаги, ожидаемый и фактический результат, повторяемость и доказательство. Важность определяется влиянием, а не числом ошибок в журнале.

Скриншоты и записи перед публикацией проверяются отдельно: без имени пользователя в пути, уведомлений, открытых документов и личных изображений. Внутренние идентификаторы дефектов и реальные отчёты закрытого проекта сюда не копируются.
