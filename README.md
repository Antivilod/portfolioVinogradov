# Vilod

Здесь собраны мои программы и учебные работы по тестированию. Одни проекты уже можно скачать и попробовать, другие пока требуют самостоятельной сборки. Ниже оставил ссылки и коротко написал, что где находится.

Основные направления: QA, автоматизация на Python и небольшие прикладные инструменты. Учебные задания вынесены в [отдельный раздел](LEARNING.md), чтобы они не смешивались с программами.

## Программы

### Vilod Switch Power (VSP)

Windows-приложение для профилей питания, ограничения FPS на поддерживаемом оборудовании и мониторинга. В проекте есть интерфейс, служба, отдельный процесс мониторинга и тесты ядра.

[Код и инструкция](https://github.com/Antivilod/Vilod-Switch-Power) · [Выпуск 0.8.0](https://github.com/Antivilod/Vilod-Switch-Power/releases/tag/v0.8.0)

Сейчас опубликованы исходники. Готового установщика нет, служба требует отдельной настройки и интеграционных проверок. Описание поддержки оборудования и ограничения находятся в README проекта. Стек: C#, .NET, WPF.

### Vilod HH

Расширение Chrome для сохранения вакансий HeadHunter и материалов о работодателях. Можно заполнить свой профиль, выгрузить материалы в JSON для внешнего помощника и импортировать результат. Отклики автоматически не отправляются.

[Код и установка](https://github.com/Antivilod/Vilod-HH) · [Выпуск 0.13.14](https://github.com/Antivilod/Vilod-HH/releases/tag/v0.13.14)

Установка через загрузку распакованной папки `extension`. Публичная версия начинается с пустого профиля. Встроенной нейросети нет. Стек: JavaScript, HTML/CSS, Chrome Manifest V3.

### Небольшие утилиты на Python

| Проект | Для чего | Как попробовать |
| --- | --- | --- |
| [Vilod Tools](https://github.com/Antivilod/vilod-tools) | SHA-256, сравнение папок, дубликаты, проверка JSON/CSV и маскирование типовых данных в логах | Python 3.10+, команды в README |
| [Vilod Test Report](https://github.com/Antivilod/vilod-test-report) | Версия 0.2.0: HTML-отчёт из JSON с дефектами, окружением и статусами | В комплекте есть вымышленный пример |

| [Vilod JSON Diff](https://github.com/Antivilod/vilod-json-diff) | Версия 0.1.0: сравнивает JSON, по умолчанию выводит только количество изменений без значений | Два вымышленных JSON-примера |
| [Vilod Text Check](https://github.com/Antivilod/vilod-text-check) | Версия 0.1.0: проверяет пробелы, переносы строк, BOM и длинные тире в UTF-8 | Только чтение, замечания в JSON |

Vilod Tools остаётся на 0.1.0; Test Report и Subtitle Check обновлены до 0.2.0. Сторонние Python-пакеты не нужны. Маскирование логов требует ручной проверки: оно может пропустить личные данные и секреты.

Собственный код семи программ распространяется по MIT. У сторонних компонентов VSP есть отдельные лицензии и уведомления, они перечислены в его репозитории.

## Тестирование и учёба

В учебных проектах есть unit-тесты, API-тесты на requests и UI-тесты на Selenium. Код части работ находится в ветках `develop`, `develop1`, `develop2` и `develop3`, поэтому обычная ссылка на `main` иногда показывает только README.

В [списке учебных работ](LEARNING.md) ссылки ведут сразу к коду. Там же отмечены недостающие части и ограничения запуска. Старые Allure-результаты не считаю подтверждением того, что тесты проходят сейчас.

## MULTIKIT

Закрытый проект в разработке. Исходники и внутренние тестовые материалы в это портфолио не входят.

Отдельно добавлен [демонстрационный чек-лист редактора](QA-EXAMPLE.md). Это новый пример оформления проверок для портфолио. Все сценарии имеют статус «Не выполнялся»; это не отчёт о фактических результатах MULTIKIT.

## Что проверено

Для обновлений от 2026-11-04 прошли 8 тестов Test Report, 9 тестов Subtitle Check, 9 тестов JSON Diff и 10 тестов Text Check в Linux, а также 8 проверок CLI. Ранее для Vilod Tools прошли 6 тестов в Linux. Для Vilod HH прошли проверка пустого профиля, контрольных сумм и синтаксиса 42 JS/MJS-файлов. Живая работа публичной версии HH в Chrome в этот прогон не проверялась.

У VSP в репозитории есть отдельный отчёт локальной Windows-проверки: 100 тестов ядра и сборка основных компонентов. Он не заменяет испытания интерфейса, службы и оборудования. Это разные уровни проверки, поэтому результаты не объединены в один процент готовности.

Если нашли ошибку в программе, можно открыть Issue в соответствующем репозитории. Для примера достаточно вымышленных данных. Реальные резюме, заполненные профили, токены и полные рабочие логи прикладывать не нужно.
